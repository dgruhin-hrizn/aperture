# v0.8.0-dev.6 — Aperture mobile, centered on Encore

A mobile app shell with bottom navigation, a persistent agentic workspace and home-screen launch support. Based on dev.5.1.

## At a glance

| Area | Change |
| --- | --- |
| Primary navigation | Discover, Library, Encore, Watching and You |
| Mobile landing | Encore, with four focused conversation starters |
| Continuity | Drafts and streaming survive route changes and sheets |
| Workbench | History and tools open in mobile sheets |
| Viewport | Keyboard-aware height, safe areas, readable form text and touch targets |
| Home screen | Standalone manifest, application icons and `/encore` launch |

## Summary for users

Open Aperture on a phone to start in Encore. Its central bottom button stays within reach as you browse. Open history without losing your draft or stopping a response. Use the workspace sheet for memory, watch plans, collections, curation and MCP connections. The You destination collects account/settings links and secondary navigation. Existing appearance preferences and write approvals continue to apply.

## Summary for admins

Desktop keeps its sidebar and Dashboard landing, with Encore available as a full page. Shared navigation definitions preserve provider/feature gates. Disabled Watching uses Picks as the fourth mobile destination. Administrative links remain available only to admins. This release changes frontend composition and navigation rather than backend permissions.

Curation's **Run now** uses PostgreSQL time so the worker can claim it immediately even when the application clock is ahead of the database.

## Database migrations

None. Upgrades from earlier Encore versions retain the existing additive migrations; no conversation, memory or managed-media data is replaced.

## API and operator notes

`/encore`, `/encore?view=plans`, `/you` and `/dashboard` are SPA routes served through the existing application fallback. The app owns one Encore runtime per authenticated account; navigating elsewhere hides it, while reload/logout/account changes end it normally. Mobile content uses the visual viewport and CSS safe-area insets. A manifest and icons support home-screen launch where the browser permits it. No service worker or offline private-data cache is introduced. Physical-device keyboard/installation behavior remains browser dependent.

## Update instructions

Pull `ghcr.io/dgruhin-hrizn/aperture:0.8.0-dev.6` and recreate the app using your existing compose configuration, or use the development channel. Reload the browser entry after updating. Home-screen shortcuts can be added using the browser's normal install/share controls; availability depends on browser and secure-context support. Existing credentials and MCP connection setup remain valid. The current standalone MCP bridge and checksum are attached.
