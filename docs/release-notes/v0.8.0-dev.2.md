# v0.8.0-dev.2 — Faster Discovery and People

Changes since v0.8.0-dev.1:

- Popular by Genre movie/TV cards render before optional Seerr checks finish. Typed status batches deduplicate overlapping rows and ignore obsolete responses after account/view changes.
- Streaming uses cached TMDb posters or the existing JustWatch artwork, avoiding a detail lookup for every uncached poster. Provider labels no longer delay row loading. Expired public charts display immediately with a localized stale notice while one background refresh runs.
- Genre pages share credential-aware caches and bounded remote concurrency, read the key once per strip, and omit the redundant per-page delay. Ranking and all configured genre/country/year filters remain unchanged.
- Browse People caches repeated page reads briefly while rechecking enabled libraries on every request. Empty pages retain the correct total, duplicate scroll events cannot duplicate appends, and account changes cancel old requests.
- Browse and Person Detail portraits use TMDb directly. Cached paths arrive with the People list; missing photos load near the viewport with shared/cancelled lookups. No Emby person-portrait requests are made. Account avatars remain separate.
- Discovery posters load lazily. Documentation and regression coverage include request deferral, stale chart refresh, cache expiry/visibility, typed IDs, pagination and portrait cancellation.

Read-only comparisons preserved People names, credit counts and ordering. Repeated page reads measured 2–8ms versus roughly 0.4 seconds per original aggregation. The browser preview recorded no Emby actor-portrait requests and no failed API responses. These samples are not end-to-end guarantees; cold external data still depends on upstream services.

No new settings or additional migrations are introduced by these optimizations. Existing appearance, preferences, library configuration and Emby Home sections are preserved. This release includes the Encore rebuild from dev.1; installations upgrading from v0.7.11-dev.13 also apply its additive migration 0120 for conversation message parts, stable keys and run ownership. See the [dev.1 notes](v0.8.0-dev.1.md).

Use `ghcr.io/dgruhin-hrizn/aperture:dev`, or pin `:0.8.0-dev.2`. Stable `:latest` is unchanged.

See [Discovery and People loading](../discovery-people-performance.md) for cache behavior, measurements and validation.
