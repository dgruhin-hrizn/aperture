# Aperture 1.0.1-dev.4

Job cards now show the next run from the server's active schedule, including its minute offset and timezone. Previously, the countdown could show the same next hour for jobs scheduled at different minutes. For example, at 7:50 a.m. Eastern, an hourly job at :45 should show 55 minutes, while a job at :05 should show 15 minutes. The schedule list now sorts using those same server times.

Turning a job on or off preserves its saved schedule. Saving a schedule also preserves its minute offset, and the settings dialog now lets you edit that offset. The dialog shows the server's scheduling timezone. Failed scheduler updates report an error so the interface does not claim that an unapplied schedule is active.

Emby jobs waiting behind another job now show **Queued**. The scheduled time is when a job becomes eligible to run; its work can start later while another Emby job finishes. This preserves the workload protection introduced in dev.3.

This release includes all dev.3 Emby stability improvements. A controlled 23-minute live test completed two movie-and-TV publishing passes without publishing failures or failed browsing requests. The repeat pass triggered no media probes and no library refresh requests. Longer observation is still needed to assess the previously reported Emby stalls.

The development image is `ghcr.io/dgruhin-hrizn/aperture:1.0.1-dev.4`, also available as `:dev` after both architectures pass their image smoke tests. Refresh the Aperture page after updating to load the corrected job cards.
