# v0.8.0-dev.3 — Shared Encore capabilities and Aperture MCP

The second Encore rebuild release, based on v0.8.0-dev.1.

## At a glance

| Area | Change |
| --- | --- |
| Shared tools | Native Encore and MCP execute the same core implementations |
| User boundaries | Exact media-server-visible catalog IDs scope search, joins and aggregates |
| MCP | Authenticated HTTP endpoint, per-user scopes, expiry and revocation |
| Local clients | Standalone stdio bridge attached to the release |
| Consultant UI | Connections, source-aware discovery, taste, schedules and regional providers |

## Summary for users

Connect your private Aperture installation to Claude, Codex or another MCP client through Encore → Connections. Encore can discover beyond your library, inspect external filmographies and title details, show regional streaming options, and look up release schedules. Semantic search combines mood with hard constraints. Result interfaces distinguish library results, external discoveries, upcoming titles and uncertain availability. The chat runtime now loads only when Encore opens.

## Summary for admins

Existing tools are extracted into focused shared core modules, with one user/catalog permission boundary. Native chat and MCP do not grant direct SQL or media-server administrative access. Connection tokens are individually scoped, expire, can be revoked, and are stored only as hashes. Private catalog reads have a total deadline and respect cancellation. Metadata lookups do not require a configured chat model; semantic lookups still need embeddings.

## Database migrations

0121 adds per-user MCP connection records. No existing configuration is replaced. Back up before upgrading. The optional bundled stdio client needs Node 22+ on the user's computer; the app container uses Node 24.

## API and operator notes

`/mcp` accepts authenticated Streamable HTTP requests. `/api/assistant/connections` supports creating, listing and revoking the current user's connections. Cookie authentication alone does not authorize MCP. This release uses bearer credentials, with no OAuth registration flow. Claude web connectors have separate network reachability requirements; private local clients need no public endpoint.

TMDb powers external metadata and movie/next-episode release information; TVmaze supplies regional broadcast/streaming calendars. Forecasts retain day precision and source/freshness information. Provider data is attributed to JustWatch via TMDb and does not prove subscription access or episode availability.

## Update instructions

Use `ghcr.io/dgruhin-hrizn/aperture:0.8.0-dev.3` or the development channel. Pull/recreate the app with your existing compose configuration. Open Encore → Connections, create a narrowly scoped client credential and follow [MCP setup](../encore-mcp.md). Download `aperture-mcp.mjs` plus checksums for local stdio clients. Stable `:latest` is unchanged.

## Validation

Lint, workspace types, production builds, deterministic tool/permission tests and a real PostgreSQL/pgvector scenario cover catalog isolation, vector relevance, hard runtime/genre constraints, numeric titles, HTTP and standalone stdio clients, scope filtering, expiry and revocation. CI runs the real database scenario using a disposable pgvector service. Existing regression suites remain required.
