# v0.7.11-dev.12 — Faster Upcoming Episodes

Changes since dev.11:

- Dashboard and Shows You Watch display the saved series list and local episodes first. TMDb forecasts arrive progressively, keeping available cards visible while the remaining batches load.
- Forecast work starts only on pages that need Upcoming Episodes. Leaving those views cancels pending browser work; other pages can use Watching controls without starting remote episode lookups.
- Public forecasts share a bounded 30-minute cache, including confirmed "no upcoming episode" results. Concurrent readers reuse in-flight requests, and four remote lookups run at a time with five-second timeouts. TMDb settings are read once per batch, and parallel requests respect the existing request pacing.
- Small authenticated batches recheck current list membership. Switching accounts ignores old responses. Missing/failed upstream data preserves known episodes and offers a read-only Refresh action, while confirmed absence clears an outdated forecast.
- Past dates are excluded from Upcoming Episodes. Ended shows remain eligible for forecast checks because synced status can be stale.
- User and admin documentation now accurately describes favorites-based Watching membership and the available settings.

Read-only measurements on an existing 202-show list: initial list and two local episodes returned in 45ms. A full lookup of its 200 TMDb-linked shows fell from 13.3 seconds to 5.0 seconds cold and 6ms cached, returning the same 22 upcoming episodes. These are backend samples, not end-to-end guarantees.

No new settings, database migrations, taste-profile changes, favorites synchronization or Emby Home changes are required by the update. Existing user/admin settings and appearance preferences are preserved.

Use `ghcr.io/dgruhin-hrizn/aperture:dev` for this development release, or pin `:0.7.11-dev.12`. `:latest` remains the stable channel.
