# v0.8.0-dev.7.1 — Mobile layout and loading repair

Fixes tool alignment, overlapping Library filters and stalled artwork requests in dev.7.

## At a glance

| Area | Fix |
| --- | --- |
| Encore tools | Full mobile width, even gutters and two complete cards per row |
| Carousels | Controls above artwork, disabled at the ends, with swipe and RTL support |
| Spacing | One owner for message/result gaps; consistent card actions and a non-shrinking composer |
| Library | Filters scroll normally on mobile instead of covering results |
| People | Proportional skeletons, loaded grid/list views and an in-page Retry action |
| Artwork | Lazy poster reads and an eight-second upstream deadline, including stalled bodies |

## Summary for users

Encore recommendations line up with the composer. Carousel arrows no longer cover posters, cards have aligned actions, and single results are centred. Detail cards wrap their content on a phone. Library filters scroll away with the page, and the Browse header has tighter mobile spacing.

Slow media-server images can no longer occupy browser connections indefinitely. The image proxy times out, allowing the UI to show fallback artwork and other queued requests to proceed. People failures end loading and offer Retry without a page reload.

## Summary for admins

Read-only diagnostics confirmed healthy API responses alongside hanging image requests. The image proxy now aborts upstream work after eight seconds, covering both response headers and body reads, and cancels when the client disconnects. Successful image responses retain their existing cache headers. Desktop navigation, permissions and Encore action approvals are unchanged.

## Database migrations

None.

## API and operator notes

The existing `/api/media/images/*` endpoint returns HTTP 504 on an upstream deadline, rather than waiting indefinitely. Missing images remain HTTP 404; other upstream failures remain HTTP 502. No new dependencies or user settings are required. Existing requests on an old running container require updating the app to receive this fix.

## Update instructions

Pull `ghcr.io/dgruhin-hrizn/aperture:0.8.0-dev.7.1` and recreate the app with the existing configuration, or use the development channel. Reload open browser tabs or home-screen shortcuts. Existing data and MCP credentials remain valid; the current bridge and checksum are attached.
