# v0.8.0-dev.8 — Encore web search and mobile reading

Adds optional public web grounding and next-reply suggestions to Encore, improves the phone transcript, and fixes Emby library output issues reported on the forum. Based on v0.8.0-dev.7.3.

## At a glance

| Area | Change |
| --- | --- |
| Encore grounding | A composer toggle enables OpenAI Responses web search for the open conversation and displays clickable sources |
| Suggested replies | Contextual follow-ups appear under the latest answer and fill an editable draft |
| Mobile transcript | 16 px text, 26 px assistant line height, compact bubbles and consistent gaps |
| Emby cleanup | Managed virtual folders are removed through the item ID endpoint |
| Library titles | TV groups can be placed with `{{group}}` and `{{type}}` uses the recipient’s UI language |
| Container | Healthcheck uses IPv4 loopback |

## Summary for users

Tap the globe beside the Encore composer to turn on Web search. It starts off when opening a conversation and uses the configured OpenAI Responses model when supported. Ask Encore to cross-check a public claim and follow the source links in the reply. Search uses the configured provider’s billing. Suggested replies are editable drafts.

Phone replies have consistent spacing, compact user bubbles and circular composer controls sized for touch. Suggested replies appear under the most recent answer when the model supplies them.

## Summary for admins

Emby removal passes the resolved library item ID to the documented virtual-folder removal operation. Existing grouped TV title templates retain the group suffix. Put `{{group}}` in a global TV title template to choose its position. `{{type}}` follows the recipient’s UI language. Preview and output share the same title formatter. User-specific custom names keep their group suffix.

## Database migrations

None.

## API and operator notes

Encore chat accepts optional `webSearch`, which defaults to false. Hosted search is scoped to native Encore and checks the configured model before starting. Existing shared tools still handle library lookups, catalog authorization and media actions. The container healthcheck uses `127.0.0.1`.

## Update instructions

Pull `ghcr.io/dgruhin-hrizn/aperture:0.8.0-dev.8` or refresh the `:dev` image. Recreate the app container with its existing configuration and reload the browser.
