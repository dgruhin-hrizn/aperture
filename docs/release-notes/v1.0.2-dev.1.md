# Aperture 1.0.2-dev.1

This development release builds on stable 1.0.1 with clearer generated-library setup and a documentation refresh.

Setup, file locations, AI Recommendations and Top Picks now share STRM/symlink guidance. It explains native Windows media servers versus Linux containers, output storage versus original-media storage, FAT32/exFAT limits, NTFS/APFS driver considerations, NAS/SMB/NFS behavior, source paths, optional sidecars and playback limitations. Neither format copies the video or guarantees Direct Play. The Emby TV description now reflects individual verified episode links.

**Check output compatibility** runs from the configuration screens using saved paths and the selected format. It checks temporary output writing, local link creation, Emby output visibility, and sampled original-directory resolution when the catalog supplies a path. Required failures and warnings are separate. Missing optional source mounts do not fail STRM video setup. Playback stays explicitly unverified until a user tests a published movie and episode. Other providers receive manual-verification guidance when automatic checks are unavailable.

Setup includes Top Picks format choices and rechecks them when saved. Its validation now distinguishes passed, failed and warning results. Temporary files are isolated and removed after checks; the check does not create a media-server library or trigger a scan.

The README and current setup, storage, model, Encore, architecture and operational guides have been updated against 1.0.1 and this dev build. Static model/price recommendations were replaced with instructions for discovery, capability checks and cost estimates. Backup defaults, release-channel publishing instructions, retired Watching-library descriptions, Windows troubleshooting and output-path API descriptions were corrected. Historical release notes remain snapshots. CI now checks current documentation links and output compatibility behavior.

Use `ghcr.io/dgruhin-hrizn/aperture:1.0.2-dev.1` or `:dev` after publication. Stable `:latest` remains 1.0.1. Back up PostgreSQL and uploaded artwork, pull and recreate the app with existing mounts, then refresh the page. No database migration is added, and saved format selections are not changed automatically.

New shared guidance is initially supplied in English across the locale catalogs, pending localization. Backend validation details also use English, consistent with the existing setup checks.
