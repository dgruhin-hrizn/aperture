# v0.8.0-dev.7.3 — Runtime input contracts throughout Aperture

Extends dev.7.2's Encore repair with comprehensive HTTP input coverage and canonical tool validation at every execution surface.

## At a glance

| Area | Change |
| --- | --- |
| HTTP input coverage | All 191 mutation operations declare an input contract or an explicit delegated validation policy |
| Canonical Zod contracts | Fill legacy body, query and path gaps across settings, users, setup, playlists, Encore and admin operations |
| Tool execution | Workbench and MCP validate the selected tool's canonical schema before invoking it |
| Documentation | Audit 107 source body types and 190 query fields against actual published contracts |
| Regression gates | Reject unclassified mutations, mismatched path names and malformed input before effects |

## Summary for users

Malformed settings, playlist and profile inputs now receive a clear validation error before saving. Partial updates, optional request bodies and native media-server item IDs remain supported. Invalid later entries in a preference batch can no longer leave earlier entries saved.

Franchise and genre deletion now use their actual names instead of an unrelated UUID parameter. Conversation titles are bounded and normalized. This release includes the OpenAI chat repair and mobile loading/layout fixes from dev.7.1 and dev.7.2.

## Summary for admins

The API installs 56 canonical Zod body contracts plus supplementary query/path validation. Existing Fastify JSON schemas continue to validate already-covered handlers. Every mutation must declare its contract or an explicit policy; new gaps fail startup and release CI. Absent bodies and empty objects remain accepted for bodyless actions. Multipart and MCP requests retain their protocol-specific validators.

Source audits catch contracts that compile but omit fields their handlers use. The full API compiles all declared request validators and response serializers, resolves published references and verifies version consistency. See the [schema compliance guide](../schema-compliance.md) for the precise coverage guarantee, including legacy response documentation limits.

## Database migrations

None.

## API and operator notes

Workbench and MCP callers now receive canonical validation, transforms and defaults before tool execution, matching the native agent runtime. Invalid arguments cannot bypass validation through a direct tool call.

The setup library-image endpoint correctly advertises its base64 JSON envelope. Multipart image and backup endpoints keep their existing upload parsers. Known scalar query inputs reject repeated values and invalid numeric bounds; existing supported query fields remain intact.

## Update instructions

Pull `ghcr.io/dgruhin-hrizn/aperture:0.8.0-dev.7.3` and recreate the app with the existing configuration, or use the development channel. Reload the browser. No credentials, data migrations or preference resets are required. Reconnect MCP clients; the versioned bridge and checksum are attached.
