# v0.8.0-dev.7.2 — Encore tool schema repair and compliance gates

Fixes OpenAI rejecting Encore's tool catalog and adds shared schema checks, based on dev.7.1.

## At a glance

| Area | Change |
| --- | --- |
| Chat failure | Replace the top-level playlist union with an object input contract |
| Runtime validation | Retain canonical create/update checks and all approval/ownership rules |
| AI/MCP boundaries | Validate serialized tool contracts before model requests or MCP registration |
| Providers | Check the complete catalog through all nine configured adapters |
| HTTP contracts | Compile the complete registered API and resolve published OpenAPI references in CI |
| Zod baseline | Align declared minimums and the workspace override with SDK v7's supported 3.25.76 baseline |

## Summary for users

An OpenAI connection test could pass while Encore immediately failed: the chat request included a playlist tool whose root schema was a union instead of an object. OpenAI rejected the entire request before producing an answer. The corrected tool uses the same flat arguments and retains the operation-specific checks. Existing OpenAI settings and credentials can stay in place.

This release includes dev.7.1's mobile tool alignment, Library filter layout and bounded artwork-loading fixes.

## Summary for admins

A shared runtime guard identifies malformed tool contracts before external requests. Every native and MCP tool is checked, and full-scope MCP discovery is exercised over HTTP. Provider tests inspect real adapter serialization; OpenAI Responses and compatible Chat Completions tests also complete streamed tool-call/result round trips.

The API schema gate compiles registered validators/serializers and verifies published references. See the [schema compliance guide](../schema-compliance.md) for coverage and the separate legacy REST contract migration scope. The installed Zod version remains 3.25.76; declarations and lockfile now explicitly require that supported baseline.

## Database migrations

None.

## API and operator notes

The `proposePlaylist` input remains flat: `operation`, `items`, and the relevant `name` or `collectionId`. The exported schema is now object-shaped. Existing action services still perform canonical validation and authorization. MCP clients should reconnect to refresh discovered tool metadata.

`/api/version` now reports the same application version as health/OpenAPI metadata, replacing a stale hardcoded value. Offline schema audits skip upload-storage initialization. Production upload initialization remains enabled; the Trakt cleanup timer no longer prevents a completed audit or shutdown from exiting.

## Update instructions

Pull `ghcr.io/dgruhin-hrizn/aperture:0.8.0-dev.7.2` and recreate the app with the existing configuration, or use the development channel. Reload the browser and retry Encore. No credential re-entry is required. Reconnect MCP clients to refresh tool definitions. The updated bridge and checksum are attached.
