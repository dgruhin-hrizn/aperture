# v0.7.11-dev.11 — Faster pages and safer cached state

Changes since dev.10:

- Recommendations, Top Picks and Watch History load the selected tab; obsolete reads are cancelled. Repeated TMDb chart reads share a short cache while local matching stays fresh.
- Fix Browse repeatedly reloading page one and replacing appended rows. Hidden tabs stay idle; filter initialization avoids equivalent repeat queries.
- Movie and TV details become usable as soon as the title loads. Optional similar titles, statistics and insights no longer hold the whole page on a loading placeholder.
- Fix movies being labelled unwatched when their watch fell outside the first 100 history entries.
- Fix the Watching browser cache being shared between accounts. Cached lists now require current account membership validation before display.
- Playlist cards fetch only five nearby preview entries. Full viewers retain all items; editor genres load on demand and seed titles resolve in one batch. Card counts use the current media server total.
- My Requests shows saved requests before fetching Seerr badges. Status enrichment is bounded, cached and checked against the request owner.
- Shared preferences remove duplicate reads and preserve unrelated settings when saving. Admin navigation and the jobs widget share adaptive polling and pause while hidden.
- Pages, the assistant and non-English dictionaries load on demand, reducing the main JavaScript download from roughly 1.53MB to 267KB compressed. Existing routes, languages, RTL, Classic and Studio light/dark remain available.

No new settings, database migrations, scoring changes or preference resets. The update does not alter existing playlists, library configuration or Emby Home sections.

Use `ghcr.io/dgruhin-hrizn/aperture:dev` for this development release, or pin `:0.7.11-dev.11`. `:latest` remains the stable channel.

See [UI performance documentation](../ui-performance.md) for cache lifetimes, access checks, failure behavior, measurements and testing.
