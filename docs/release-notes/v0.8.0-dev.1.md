# v0.8.0-dev.1 — Encore workspace and modern agent runtime

The first Encore rebuild release, based on v0.7.11-dev.13.

## At a glance

| Area | Change |
| --- | --- |
| Encore | Responsive conversation workspace, new composer and poster cards |
| Agent runtime | AI SDK 7, assistant-ui 0.15 and current provider adapters |
| Persistence | Server-owned, idempotent messages and restored conversation context |
| Runtime | Docker and CI use Node 24 |

## Summary for users

Encore now restores saved conversation context for follow-up questions. The new workspace supports mobile conversation navigation, light/dark appearance, cancellation and visible retry controls. Poster cards and result surfaces follow the selected Aperture theme. Numeric movie titles remain searchable, and semantic matches keep their relevance order.

## Summary for admins

Provider adapters are upgraded together with the AI SDK. Existing provider/model configuration and embedding tables are retained. Local inference respects cancellation. Chat no longer requires embeddings for non-semantic questions; semantic search reports a missing embedding configuration when used. Interactive runs have output, step and timeout bounds. The original read-only tools remain available in this stage.

## Database migrations

0120 adds full message parts, stable message keys and expiring per-conversation run ownership. Existing transcripts remain readable, including saved tool results. Back up the database before upgrading; application rollback after migration is possible, but old browser message writes are intentionally rejected by this release.

## API and operator notes

`POST /api/assistant/chat` requires an owned `conversationId`. The server loads authoritative history and accepts only the latest user text from the browser. Conversation GET returns native UI messages. Legacy browser transcript POST returns 410. Concurrent runs in the same conversation return 409.

## Update instructions

Use `ghcr.io/dgruhin-hrizn/aperture:0.8.0-dev.1` or the development channel. Pull and recreate the app container using your existing compose file. Check `/health`, reopen an old Encore conversation, ask a follow-up, and verify light/dark and mobile layouts. Stable `:latest` remains unchanged.

## Validation

Migration validation uses an isolated PostgreSQL/pgvector database. Automated Encore scenarios cover legacy tool restoration, numeric titles, persisted follow-ups, forged client history, user ownership, concurrent requests and idempotent regeneration. UI verification uses an isolated fixture model, never production Emby writes. Repository validation, production builds and existing regression suites are release gates.

## Full changelog

- Upgrade AI SDK, assistant-ui, all configured provider adapters and Node runtime.
- Replace manual SSE rewriting and client-count persistence with standard streaming and owned server history.
- Redesign Encore workspace, composer, conversation navigation and result cards.
- Repair argument normalization and semantic ranking; add regression coverage and CI execution.
