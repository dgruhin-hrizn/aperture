# v0.8.0-dev.4 — Encore memory, watch plans and Emby actions

The third Encore rebuild stage adds a personal workbench and shared agent capabilities.

- **Memory:** Save, inspect, correct, expire and forget account-scoped facts with Encore/MCP provenance. Persistent preferences use canonical Taste Profile interests and active-model embeddings when available. Temporary facts do not affect global recommendation interests. Forgetting preserves interests edited elsewhere.
- **Watch plans:** Draft from exact movie/episode IDs, explicit local viewing windows and an IANA timezone. Check live visibility, runtime, watched state and remaining playback. Keep episode order, account for breaks, reject overlapping or ambiguous daylight-saving windows, and explain unplaced items. Edit windows, recheck, save and export a calendar copy.
- **Collections:** Prepare and approve exact playlist or Home-row proposals inline or from the Collections tab. Only tracked, owned resources are changed. Private playlists use the signed-in user's Emby credentials; unrelated Home configuration and manual playlist edits are preserved.
- **Recovery:** Persist action state, exact playlist and Home section IDs, revision checks and receipts. Serialize changes per collection across processes. Repeated successful actions return the receipt. Interrupted appends reconcile membership. Unknown creation outcomes never trigger a blind second creation; identify the existing playlist through a management-authorized Emby details link.
- **MCP:** Separately selectable memory, plan, playlist and Home permissions. Read-only connections remain read-only. Native Emby execution requires the inline approval button; external clients receive a separate explicit execution tool with mutation annotations.

## Database and operations

Migration 0122 adds memories, plans, managed collections and action records. Existing taste controls remain authoritative. No media files are deleted by Encore. Home rows require Emby support; unsupported versions return a visible failure rather than a success claim. Jellyfin consultation and planning work, while managed playlist/Home writes currently require Emby.

Model context is bounded; recent conversation groups stay intact and durable memories are supplied separately as data. Current history/catalog facts are fetched through scoped tools rather than injected through an unscoped history query. Upstream chat and embedding providers receive data needed for enabled AI operations, according to the installation's existing provider configuration.

## Validation

Lint/typecheck, production build, real PostgreSQL/pgvector and deterministic agent tests cover memory provenance/correction/forgetting, cross-user attempts, hard runtimes, episode order, timezone/DST checks, stale plan revisions, ICS escaping, approval boundaries, duplicate and interrupted Emby writes, manual additions and Home preservation. Browser checks use an isolated preview account and synthetic media; no production Emby mutation is performed.

Use `ghcr.io/dgruhin-hrizn/aperture:0.8.0-dev.4` or the development channel. Stable `latest` is unchanged. The standalone MCP bridge and checksum are attached. Recurring curation follows in stage four; suggestions remain the default.
