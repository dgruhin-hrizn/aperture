# Aperture 1.0.2

Aperture 1.0.2 brings the output guidance, compatibility checks, and documentation refresh from dev.1 and dev.2 to the stable channel.

## Choose STRM or symlinks with clearer guidance

Setup, file locations, AI Recommendations and Top Picks now share the same explanations. They cover native Windows media servers versus Linux containers, generated-output storage versus original-media storage, FAT32/exFAT limitations, NTFS/APFS driver considerations, NAS/SMB/NFS mounts, path mappings, and optional artwork/subtitle sidecars.

Both formats reference existing videos without copying them. Neither guarantees Direct Play or better picture quality. Symlinks can cross filesystems; compatibility depends on where the links are stored and whether the media server can resolve their targets. Existing format selections are preserved.

## Check output compatibility

The new **Check output compatibility** action checks saved output paths and the selected format. It separates local output writing and symlink creation from Emby output visibility and sampled original-directory resolution. Missing optional source mounts no longer automatically fail STRM setup. Top Picks choices participate in setup validation.

Temporary directories use normal published-output creation permissions so a media server running under another account can inspect them. Check files are removed afterward; the action creates no media-server library and triggers no scan. Required failures, advisory warnings and unavailable automatic provider checks are distinct.

Playback remains explicitly unverified. Publish a small selection and test a movie and episode in your media server, including audio, subtitles and seeking, before relying on scheduled publishing.

## Updated documentation

The README and current setup, storage, model, Encore, architecture and deployment guides have been refreshed. Corrections include retired Watching-library descriptions, backup defaults, output-path API descriptions, Windows recovery advice and tag-driven publishing instructions. Model guidance now uses discovery, capabilities and cost estimates instead of fixed model rankings and price tables. Historical release notes remain snapshots.

Validation includes eight output regression tests, local links across 86 current Markdown guides, syntax checks for seven Compose configurations, and the full release regression suite. Both AMD64 and ARM64 images pass their smoke tests before publication. Live checks on Emby 4.11.0.13 verified output visibility and sampled target resolution; client playback and other operating-system/filesystem combinations are separate checks.

New shared guidance is initially in English pending localization. No database migration is added.

## Updating

Use `ghcr.io/dgruhin-hrizn/aperture:latest` for the stable channel, or pin `ghcr.io/dgruhin-hrizn/aperture:1.0.2`. The `:1.0` tag also follows this release. Users switching from `:dev` should change their image tag before pulling and recreating the app.

Back up PostgreSQL and uploaded artwork, retain the existing database and mounts, and update the Aperture app container. Refresh the page afterward and confirm `/health` reports **1.0.2** with a connected database. The release includes the standalone MCP bridge and its SHA-256 checksum.
