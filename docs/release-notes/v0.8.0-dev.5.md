# v0.8.0-dev.5 — Opt-in Encore curation and complete workbench

The final Encore rebuild stage adds durable recurring curation to the modern assistant-ui workspace and shared MCP capability layer.

## For users

- Create a paused rule for an existing managed playlist, with a movie mood/filters or exact-show episode recipe, runtime/rating/watched constraints and a daily/weekly local schedule.
- Explicitly enable recurring updates; edit, pause, run now or remove the rule in Encore → Curation. Every edit pauses it for renewed opt-in.
- See next/last run, selected titles, actual membership changes and failure details. Rules do not send external messages or create calendar events.
- Manual additions remain manual even when selected by a later recipe. Manual removals persist across recipe changes; adding an item back clears its exclusion during reconciliation.
- New release highlights and a rewritten Encore guide explain the complete workspace: Conversation, Memory, Watch Plans, Collections, Curation and Connections.

## For operators

Migration 0123 adds recurring rules, run history and persistent manual exclusions. The scheduler checks due work each minute. Leases and unique scheduled-run keys prevent duplicate worker claims. A row lock coordinates pause/edit with mutations; persisted action IDs recover already completed writes after interruption. Only managed collections are refreshed, through the same scoped action services used by native chat and MCP.

Access, credentials and authority are checked on each run. Failure or empty eligibility pauses a rule and records why. A revoked/expired MCP connection stops rules it authorized; users can explicitly reauthorize them directly in Encore. Filter-only curation does not invoke a chat model. Semantic recipes use the existing embedding configuration and its associated costs. Date-only release forecasts remain distinct from local availability.

Recurring wall-clock times use compatible daylight-saving behavior: spring gaps shift forward and repeated fall times use the first occurrence. Watch-plan windows continue to reject ambiguous/nonexistent local times. An already executing write may finish before a pause returns.

## Validation

Zero-error lint/type checks, frozen-lockfile installation, production build, all Encore scenarios with real PostgreSQL/pgvector, and existing application regression suites. Coverage includes cross-user isolation, HTTP/stdio MCP, correction/forgetting, runtime and DST constraints, ICS export, explicit approvals, unknown creation reconciliation, partial writes, simultaneous workers, expired leases, completed-write recovery, manual edits across recipe changes, revoked authority and provider failures. Browser verification uses an isolated account and synthetic records; production Emby data is not mutated.
